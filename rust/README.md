# rust/

Rust core and behavior-parity crates for the OctoBeat port.

Crates in this directory are generated and driven by `rust-anything` 2.0.2.
Each unit crate contains:

- `rust-anything.json` — the bridge plan;
- `cases.jsonl` — behavior recorded from the original Python code;
- `custom_cases.jsonl` — curated real-world inputs;
- `src/port.rs` — the hand-written Rust port;
- `src/lib.rs` and `python/` — generated bindings (do not edit);
- `README.md` — generated usage notes.

Ported units:

- `metadata-normalize-rs` — 1,316 cases (`../desktop/docs/PILOT-001.md`);
- `cover-provider-rs` — 240 cases, uses symphonia for raw metadata
  (`../desktop/docs/PILOT-002.md`).

`rust/PORT_MAP.md` is generated by `rust-anything map . --write`; commit it so
upstream changes to the original Python are visible at the next checkpoint.

## Loop

```sh
rust-anything record <crate> --inputs <crate>/custom_cases.jsonl
rust-anything build <crate>
rust-anything diff <crate>
rust-anything gate <crate>
rust-anything map ..
```

`gate` is the definition of done: formatting, clippy with warnings as errors,
tests, no unsafe, no unimplemented functions, complete API, and 100% of the
recorded cases.

## Notes

- `target/`, `*.so`, `__pycache__/` and `.rust-anything/` are ignored.
- The PyO3 bindings are a transition mechanism for validating behavior inside
  the existing Python app. The final C++/Qt application will link the Rust core
  directly and will not ship Python.
- Keep generated `src/lib.rs` and `python/` untouched; edit `src/port.rs` and
  run `rust-anything refresh` only after changing a signature.
- `music.db` and the user's music files are not stored here.
